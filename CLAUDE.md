# CLAUDE.md — open-upstream-watch

**日本語 → English**

## 日本語

### 役割
RPoem が互換実装している元と、Rust + Leptos(WASM・trunk)テンプレートの部品の新版を監視し、追従作業を準備して、関門を通ったものだけを自動マージする。画面は Leptos(WASM)。ログインはメールの OTP(既存の `open-easy-web` に委譲)。配置先は `https://easy-web.tokyo/leptos-rs/`(デモは `/demo/`)。

### 構成
- `crates/watch-types`: 共有の型(serde のみ、wasm でも使える)。
- `crates/watch-core`: 設定・GitHub/crates.io クライアント・状態・**関門(`gate.rs`)**・git 操作・porter・破壊的変更の判定(`analysis.rs`、`aruaru-llm` 連携は `services.rs`)・メール(`notify.rs`)・1 周のパイプライン(`pipeline.rs`)。
- `crates/watch-server`: Poem のサーバー(OTP ログインの委譲・状態 API・スケジューラ・`--once`/`--test-alert`/`--make-demo`)。
- `ui/`: Leptos CSR(trunk)。`demo-status.json` は `--make-demo` で生成(版は実データ、ジョブはサンプルと明記)。
- `config.example.toml`: 設定の見本。`config.toml`(git 管理外)に許可メール・通知先を書く。

### ルール
1. **秘密を表示・記録・コミットしない**(トークン・SMTP パスワード・許可メール)。txt のパスか環境変数で渡す。
2. **関門は「許可したものだけ通す」**。許可リストの拡大・`allow_code_merge`・`dry_run` の既定の変更は、必ずユーザーに確認する。AI(`aruaru-llm`)の判定は「見送り」にしか使わない。
3. 外部から来る JSON(GitHub・crates.io・検索・LLM)は `rust-json` の `parse_secure`(サイズ・深さ・重複キーの上限つき)で読む。
4. 変更したら `cargo test --workspace` と(画面を触ったら)`trunk build` + `node scripts/e2e-ui.js` を実行。**実ブラウザで確認してから**完了と言う。
5. Leptos では、`await` の後に**破棄済みの signal を `.get()`/`.set()` するとパニック**する。`try_get`/`try_set` を使う(実際に踏んだ)。

### 落とし穴
- シェルの heredoc で Python に `\n` を渡すと本物の改行になる。補助スクリプトは先にファイルへ書く。CRLF のファイルは置換が静かに失敗する(Edit ツールを使う)。
- `git status --porcelain` の出力は**先頭の空白が意味を持つ**。`trim` すると 1 行目のパスが壊れる(実際に踏んだ。今は `git diff --name-only` を使う)。
- poem は GitHub のリリースが古い v2.0.0 で止まっている。新版は crates.io(`kind = "crate"`)。
- Git Bash は `/mnt/...` を書き換える(WSL を使う場合は PowerShell)。

## English

### Role
Watches the upstreams RPoem re-implements and the parts of the Rust + Leptos (WASM, trunk) template, prepares the follow-up work, and merges automatically only what passes the gate. Dashboard in Leptos (WASM); login by e-mail OTP delegated to the existing `open-easy-web`. Deployed at `https://easy-web.tokyo/leptos-rs/` (demo at `/demo/`).

### Layout
`crates/watch-types` (shared serde types, wasm-friendly), `crates/watch-core` (config, GitHub/crates.io client, state, **the gate `gate.rs`**, git ops, porters, breaking-change analysis `analysis.rs` with aruaru-llm in `services.rs`, mail `notify.rs`, the cycle `pipeline.rs`), `crates/watch-server` (Poem server: OTP delegation, status API, scheduler, `--once` / `--test-alert` / `--make-demo`), `ui/` (Leptos CSR with trunk; `demo-status.json` is generated by `--make-demo`: real versions, sample jobs), `config.example.toml`.

### Rules
1. Never print, log or commit secrets (tokens, SMTP password, the allowed e-mail). Pass txt paths or environment variables.
2. The gate lets through **only what is explicitly allowed**. Always ask the user before widening an allow-list, enabling `allow_code_merge` or changing the `dry_run` default. aruaru-llm's opinion may only *hold a change back*.
3. External JSON (GitHub, crates.io, search, LLM) is read with `rust-json` `parse_secure` (size / depth / duplicate-key limits).
4. After changes run `cargo test --workspace`, and for UI work `trunk build` + `node scripts/e2e-ui.js`. Verify in a real browser before saying it is done.
5. In Leptos, reading or writing a **disposed signal after an `await` panics**; use `try_get` / `try_set` (hit for real).

### Pitfalls
Escapes in shell heredocs turn `\n` into real newlines (write helper scripts to files first); CRLF files make scripted replacement fail silently (use the Edit tool); leading spaces in `git status --porcelain` output are significant (trimming broke the first path; `git diff --name-only` is used now); poem's GitHub releases stop at v2.0.0 (use crates.io, `kind = "crate"`); Git Bash rewrites `/mnt/...` paths.
